# 同來源輸出自動子資料夾設計

## 目標

當使用者在批次縮放的指定資料夾模式中，選到與來源資料夾相同的位置時，
程式不應安靜失敗，也不應只讓既有衝突偵測阻擋操作。
系統應自動改用來源資料夾內的命名子資料夾，讓使用者能順利輸出縮放結果，
同時避免覆寫原圖或把輸出檔混入來源序列。

## 使用情境

使用者有一個來源資料夾 `cloud`，裡面放置序列圖檔。
他想把整批圖片縮小為 0.5 倍，且輸出位置與來源位置相同。
程式應自動將輸出資料夾解析為 `cloud\cloud_x0.5`，
並在 log 顯示已自動改用該資料夾。

## 範圍

第一版只支援批次縮放工具。
抽幀刪除的「複製保留幀到指定資料夾」與批次改名的「複製改名到指定資料夾」
暫不納入，避免一次修改三個工具的輸出語意。

## 不做的事

- 不直接在來源資料夾內輸出 `cloud_x0.5.png` 這類同層檔名。
- 不覆寫原始檔。
- 不改變批次縮放的覆寫原始模式。
- 不在 planner 或 executor 中彈出 UI 對話框。

## 行為設計

使用者執行批次縮放並選擇目標資料夾後，ViewModel 呼叫新的輸出資料夾解析服務。

若目標資料夾與來源資料夾不同，維持使用者選擇的目標資料夾。

若目標資料夾與來源資料夾相同，解析服務回傳自動子資料夾：

- 倍率模式：`{來源資料夾名}_x{倍率}`，例如 `cloud_x0.5`。
- 絕對尺寸模式：`{來源資料夾名}_{寬}x{高}`，例如 `cloud_800x600`。
- 等比限制在框內時，若使用既有絕對尺寸模式搭配維持比例，仍使用 `{來源資料夾名}_{寬}x{高}`。

若自動子資料夾內已有同名目標檔，仍使用既有衝突偵測標示錯誤，
不覆蓋既有檔案。

## 架構設計

新增 `IOutputFolderResolver` 與 `OutputFolderResolver`。
此服務為 pure function 風格，不讀寫檔案、不顯示 dialog。

輸入：

- 來源資料夾路徑。
- 使用者選擇的目標資料夾路徑。
- 縮放選項。

輸出：

- 解析後的目標資料夾路徑。
- 是否自動改用子資料夾。
- 可寫入 log 的提示訊息。

`ResizeToolViewModel.ExecuteAsync()` 在使用者選完資料夾後呼叫 resolver，
再把解析後的路徑寫入 `ResizeOptions.TargetFolderPath`。
`ResizePreviewService`、`ResizePlanner` 與 `ImageResizeExecutor`
只接收已解析後的目標路徑，不處理 UI 決策。

## 錯誤處理

來源資料夾為空或無效時，維持既有無檔案與不可執行行為。
使用者取消選擇資料夾時，維持既有取消 log。
自動產生的資料夾名稱若含非法字元，應由 resolver 轉成安全名稱；
若仍無法產生安全名稱，執行流程應記錄 log 並中止，不進入 executor。

## 測試策略

新增 `OutputFolderResolverTests`：

- 來源與目標不同時，保留使用者目標資料夾。
- 來源與目標相同時，產生來源內子資料夾。
- 路徑大小寫不同但指向同一資料夾時，仍判定為相同。
- 倍率 0.5 時產生 `_x0.5` 後綴。
- 絕對尺寸時產生 `_800x600` 後綴。

更新 `MainViewModelCanExecuteTests` 或新增對應 ViewModel 測試：

- 使用者選到來源資料夾時，executor 收到自動子資料夾路徑。
- log 顯示已自動改用輸出資料夾。
- 自動子資料夾內同名檔已存在時，預覽標錯且不執行。

## 驗收條件

- 使用者在批次縮放指定資料夾模式中選到來源資料夾時，
  程式自動改用來源內子資料夾輸出並寫入 log。
- 倍率模式 `0.5` 的自動資料夾名稱包含 `_x0.5`。
- 目標子資料夾已有同名檔案時，預覽標示衝突且執行按鈕停用。
- 來源與目標不同時，行為與現有指定資料夾輸出一致。
